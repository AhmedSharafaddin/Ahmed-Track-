# مركز القيادة — COMMAND CENTER

نظام شخصي لتتبّع الأولويات والأهداف والمهام المهنية، يعمل على **لابتوب ويندوز** و**الآيفون** بنفس البيانات. التكلفة صفر.

| القسم | ما يفعله |
|---|---|
| **اليوم** | ٣ أولويات فقط، وحلقات تمتلئ مع كل إنجاز، وسلسلة الأيام المتتالية. تحتها اقتراحات مرتّبة حسب الأهمية والموعد، و«أيضًا اليوم» للمستحق والمتابعات. ما لا يُنجز يعود في اليوم التالي ويُعدّ «ترحيلًا». |
| **القوائم الذكية** (مثل To Do) | هام (النجمة) · مخطط (حسب الموعد) · المُسندة (لكل شخص، مع موعد متابعة وزر «تابعت») · الوارد (ما لا مجال له). |
| **المجالات** | كل مجال قائمة مستقلة: أسس تيليكوم · الجوبي · شخصي (قابلة للتعديل). |
| **تفاصيل المهمة** | لوحة جانبية تحفظ تلقائيًا: خطوات، أولويات اليوم، مهم/عاجل، موعد، تكرار، إسناد ومتابعة، مجال، هدف، ملاحظات. |
| **المصفوفة** | أيزنهاور؛ اسحب المهمة بين المربعات لتغيير تصنيفها. |
| **الأهداف** | التقدّم يُحسب من المهام المنجزة؛ نشط / مؤجل بوعي / تحقق. |
| **المراجعة** | أرقام الأسبوع، الإنجاز يومًا بيوم، توازن المجالات، ما يجب ترتيبه، وتأمّل مكتوب. |
| **وضع التركيز** | مؤقّت ١٥/٢٥/٥٠ دقيقة لمهمة واحدة بخطواتها. |
| **Widget** | نافذة صغيرة تعرض أولويات اليوم فقط. |

**الكتابة السريعة:** `!` مهم · `!!` مهم وعاجل · `@الاسم` إسناد · `#المجال` تصنيف. اختصارات: <kbd>N</kbd> مهمة جديدة، <kbd>/</kbd> بحث، <kbd>Esc</kbd> إغلاق.

---|---|

| **المجالات** | المهام مقسّمة حسب الجهة: أسس تيليكوم · الجوبي · شخصي / تطوير ذاتي (قابلة للتعديل). |
| **الأهداف** | كل هدف مرتبط بخطواته، ونسبة التقدّم تُحسب تلقائيًا من المهام المنجزة. |
| **المراجعة** | إحصاءات الأسبوع (يبدأ السبت): المنجز، نسبة العمل الاستراتيجي، المتأخر، المهام التي تتكرر في الترحيل + تأمّل مكتوب. |

## ١) التشغيل الأول (محليًا، دون أي إعداد)

التطبيق ملفات ثابتة (HTML/CSS/JS) بلا خطوة بناء. لتجربته على اللابتوب:

```bash
cd Ahmed-Track-
python -m http.server 8080
```

ثم افتح `http://localhost:8080`. البيانات تُحفظ في المتصفح على هذا الجهاز فقط.

> فتح `index.html` مباشرة بنقرة مزدوجة لا يكفي — المتصفح يمنع الوحدات (modules) من `file://`.

## ٢) النشر على رابط دائم مجاني (مطلوب للآيفون)

المستودع **خاص (Private)**، وGitHub Pages المجاني لا ينشر من مستودع خاص. لذلك نستخدم **Cloudflare Pages** (مجاني، HTTPS، يتحدّث تلقائيًا مع كل push):

1. ادخل [dash.cloudflare.com](https://dash.cloudflare.com) وأنشئ حسابًا مجانيًا.
2. **Workers & Pages** ← **Create** ← تبويب **Pages** ← **Connect to Git**.
3. اربط حساب GitHub واختر المستودع `Ahmed-Track-`.
4. الإعدادات: **Framework preset:** None · **Build command:** فارغ · **Build output directory:** `/`
5. **Save and Deploy**. ستحصل على رابط مثل `https://ahmed-track.pages.dev`.

> بديل: إن جعلت المستودع عامًا (Public) يمكنك استخدام GitHub Pages: Settings ← Pages ← Deploy from branch ← `main` / `root`. لا توجد بيانات شخصية في الكود؛ بياناتك في المتصفح أو في Firebase.

## ٣) التثبيت كتطبيق

**ويندوز (Edge أو Chrome):** افتح الرابط ← قائمة المتصفح (⋯) ← **التطبيقات** ← **تثبيت مركز القيادة**. يظهر في قائمة ابدأ ويمكن تثبيته على شريط المهام.
- **الـWidget:** انقر بزر الفأرة الأيمن على أيقونته في شريط المهام ← «أولويات اليوم (Widget)»، أو من الإعدادات ← «فتح نافذة الـWidget». صغّر النافذة وضعها في زاوية الشاشة.

**آيفون (Safari):** افتح الرابط ← زر المشاركة ← **إضافة إلى الشاشة الرئيسية**. يفتح بملء الشاشة كتطبيق مستقل ويعمل دون إنترنت.

**حدود صريحة:**
- لا يستطيع أي تطبيق ويب وضع Widget على **الشاشة الرئيسية للآيفون** — هذه ميزة للتطبيقات الأصلية فقط. البديل الحالي: أيقونة تفتح مباشرة على أولويات اليوم.
- على ويندوز، «الـWidget» نافذة تطبيق صغيرة، وليست لوحة Widgets الخاصة بويندوز.

## ٤) تفعيل المزامنة بين اللابتوب والآيفون (Firebase — مجاني)

بدون هذه الخطوة كل جهاز له بياناته المنفصلة. بعدها: أي تغيير يظهر على الجهاز الآخر خلال ثوانٍ، والتطبيق يعمل دون إنترنت ويزامن عند عودة الاتصال (مثل Microsoft To Do).

1. **إنشاء المشروع:** [console.firebase.google.com](https://console.firebase.google.com) ← **Create a project** (يمكن تعطيل Google Analytics). الخطة المجانية **Spark** لا تطلب بطاقة.
2. **تسجيل الدخول:** Build ← **Authentication** ← Get started ← Sign-in method ← **Email/Password** ← Enable.
3. **قاعدة البيانات:** Build ← **Firestore Database** ← Create database ← اختر موقعًا قريبًا (أوروبا مثلًا) ← **Production mode**.
4. **قواعد الحماية:** Firestore ← تبويب **Rules** ← الصق محتوى ملف `firestore.rules` من هذا المستودع ← **Publish**.
5. **إعدادات الويب:** ⚙️ Project settings ← Your apps ← أيقونة الويب `</>` ← سجّل تطبيقًا (بدون Hosting) ← انسخ كائن `firebaseConfig`.
6. الصقه في `js/config.js` بدل `null`، ثم commit + push (Cloudflare ينشر تلقائيًا).
7. **النطاق المسموح:** Authentication ← Settings ← **Authorized domains** ← أضف نطاقك (مثل `ahmed-track.pages.dev`).
8. افتح التطبيق ← ⚙️ الإعدادات ← **إنشاء حساب**. أول دخول يرفع بيانات هذا الجهاز إلى حسابك.
9. على الجهاز الآخر: ⚙️ ← **دخول** بنفس الحساب.
10. **أغلق التسجيل أمام الآخرين** بعد إنشاء حسابك: Authentication ← Settings ← User actions ← ألغِ **Enable create (sign-up)**.

> قيم `firebaseConfig` ليست أسرارًا (تظهر لأي متصفح يفتح التطبيق). الحماية الحقيقية = قواعد Firestore (كل مستخدم يرى بياناته فقط) + إغلاق التسجيل.

## ٥) حماية البيانات

- **الإعدادات ← نسخة احتياطية ← تصدير** يحفظ كل شيء في ملف JSON. افعلها أسبوعيًا مع المراجعة.
- على الآيفون: استخدم التطبيق **من الشاشة الرئيسية** لا من Safari مباشرة؛ Safari قد يمسح بيانات المواقع غير المستخدمة لفترة، والتطبيقات المضافة للشاشة الرئيسية مستثناة من ذلك. مع تفعيل المزامنة تصبح نسختك الأساسية في السحابة.

## ٦) البنية التقنية (للمراجعة أو لمطوّر لاحق)

```
index.html            هيكل الصفحة + التنقل
styles.css            نظام التصميم (فاتح/داكن، RTL، جوال/سطح مكتب)
js/app.js             التشغيل والأحداث والعرض
js/views.js           الشاشات ولوحة التفاصيل ووضع التركيز
js/model.js           المنطق: القوائم الذكية، الاقتراحات، التكرار، الإسناد، الترحيل
js/store.js           طبقة البيانات: محرّك محلي (localStorage) + محرّك سحابي (Firestore)
js/utils.js           التواريخ (الأسبوع يبدأ السبت)، مصفوفة أيزنهاور، التنسيق
js/config.js          إعدادات Firebase (null = محلي فقط)
sw.js                 العمل دون اتصال
manifest.webmanifest  التثبيت كتطبيق + اختصار الـWidget
firestore.rules       قواعد الحماية في Firebase
```

**قرارات أساسية:**
- **تطبيق ويب قابل للتثبيت (PWA)** بدل تطبيقين منفصلين: كود واحد يعمل على ويندوز والآيفون، بلا متجر تطبيقات وبلا رسوم مطوّر Apple.
- **بلا أدوات بناء:** أي تعديل = تعديل ملف ثم push. أقل نقاط فشل، وأسهل للصيانة.
- **محلي أولًا:** التطبيق يعمل كاملًا دون حساب ودون إنترنت؛ السحابة طبقة مزامنة اختيارية فوقه.
- **بيانات منفصلة لكل مستخدم** (`users/{uid}/...`): نفس البنية تصلح لاحقًا لعدة مستخدمين في الشركة.

**نموذج البيانات:**
- `areas`: الاسم، اللون، الترتيب
- `goals`: العنوان، لماذا، المجال، الموعد المستهدف، الحالة (active / paused / done)
- `tasks`: العنوان، ملاحظات، المجال، الهدف، مهم، عاجل، الموعد، الحالة، تاريخ التركيز (Top 3)، عدد مرات الترحيل، تاريخ الإنجاز، وفي الإصدار ٢: `steps` الخطوات، `repeat` التكرار، `assignee`/`assignedAt`/`followUp` الإسناد والمتابعة (حقول اختيارية — البيانات القديمة تعمل كما هي، ولا تغيير على قواعد Firestore)
- `reviews`: معرّفها = تاريخ سبت الأسبوع؛ الإنجاز، المعطّلات، التالي

**تحديث نسخة مثبّتة:** عند تعديل ملفات التطبيق ارفع `VERSION` في `sw.js` حتى تتحدّث النسخ المثبّتة.
