# تثبيت ITrack على سيرفر الجهة

تطبيق واحد: «العمل» (التقارير اليومية والاعتماد والفريق) و«مهامي» (المهام والأهداف والتركيز والصوت). يعمل على سيرفر الجهة نفسها، والبيانات في ملف SQLite عندها. لا يحتاج إنترنت إلا إن فُعّل ذكاء اصطناعي سحابي.

**المتطلبات:** Node.js 22.13 أو أحدث (LTS)، أو Docker. ذاكرة 256MB تكفي لمئات المستخدمين.

## ١) التشغيل

### Docker (الأبسط على لينكس)
```bash
docker build -f itrack/server/Dockerfile -t itrack .
docker run -d --name itrack -p 8080:8080 -v itrack-data:/data --restart unless-stopped itrack
```

### ويندوز سيرفر
1. ثبّت Node.js LTS من nodejs.org.
2. انسخ المستودع إلى `C:\itrack`.
3. للتجربة: شغّل `itrack\server\start-windows.bat`.
4. للتشغيل الدائم كخدمة: نزّل [NSSM](https://nssm.cc) ثم نفّذ:
   ```bat
   nssm install ITrack "C:\Program Files\nodejs\node.exe" "C:\itrack\itrack\server\server.mjs"
   nssm set ITrack AppDirectory C:\itrack
   nssm start ITrack
   ```

### لينكس (systemd)
```ini
# /etc/systemd/system/itrack.service
[Unit]
Description=ITrack
After=network.target
[Service]
WorkingDirectory=/opt/itrack
ExecStart=/usr/bin/node itrack/server/server.mjs
Restart=always
User=itrack
Environment=NODE_NO_WARNINGS=1
[Install]
WantedBy=multi-user.target
```
ثم `systemctl enable --now itrack`.

## ٢) HTTPS (ضروري)
الميكروفون وتثبيت التطبيق على الجوال يعملان على HTTPS فقط. هناك طريقتان:
- شهادة مباشرة: `TLS_CERT` و`TLS_KEY` في `itrack.env`.
- وكيل عكسي (IIS أو Nginx أو Caddy) يحوّل إلى المنفذ 8080، مع `TRUST_PROXY=1`.

## ٣) أول استخدام
1. افتح `https://<عنوان-السيرفر>/itrack/`.
2. **أول حساب** يُنشأ هو مسؤول الجهة. بعده يُغلق التسجيل الحر: `SIGNUP=invite` افتراضي.
3. أنشئ الإدارات، ثم الوظائف وتوصيفها، ثم الأعضاء.
4. كل عضو تضيفه تظهر له **رسالة دعوة** فيها رابط ورمز. أرسلها له بالبريد أو واتساب. يفتح الرابط ويختار كلمة مرور، فيدخل مباشرة.
5. من نسي كلمة مروره: افتح «الهيكل»، ثم العضو، ثم «رمز إعادة تعيين كلمة المرور». لا يحتاج النظام خادم بريد.

## ٤) الإعداد (`itrack.env` في مجلد التشغيل)
القيم كلها اختيارية. راجع `itrack.env.example`. أهمها:

| المتغير | الافتراضي | المعنى |
|---|---|---|
| `PORT` | 8080 | المنفذ |
| `DATA_DIR` | `./data` | مكان القاعدة والنسخ الاحتياطية |
| `BACKUP_KEEP` | 14 | عدد النسخ الاحتياطية اليومية المحفوظة |
| `SIGNUP` | invite | `open` للتسجيل الحر |
| `AI_URL` / `AI_KEY` | — | الذكاء الاصطناعي، أي خدمة متوافقة مع OpenAI |

### الذكاء الاصطناعي (الإدخال الصوتي ومحضر الاجتماع)
- **سحابي:** `AI_URL=https://api.openai.com/v1` و`AI_KEY=...` (أو أي مزوّد متوافق مثل Groq). تكلفته على الجهة حسب الاستخدام: [TBD] بحسب المزوّد.
- **محلي:** خادم Whisper (faster-whisper أو whisper.cpp) مع Ollama على نفس الشبكة، ويعرضان `/v1`. بهذا لا يخرج صوت الاجتماعات من الشركة. جودة العربية واللهجة اليمنية تُختبر بتسجيل حقيقي قبل الاعتماد.
- دون إعداد: زر الميكروفون يعرض رسالة «غير مفعّل»، وبقية التطبيق يعمل.

## ٥) النسخ الاحتياطي والاستعادة
- نسخة تلقائية عند التشغيل ثم كل ٢٤ ساعة: `data/backups/itrack-YYYY-MM-DD.db`. تُنسخ دون إيقاف الخدمة.
- نسخة فورية: `node itrack/server/server.mjs backup`.
- **انسخ مجلد `backups` إلى جهاز آخر دوريًا**، فالنسخة على نفس القرص لا تحمي من تلفه.
- الاستعادة: أوقف الخدمة، ثم ضع النسخة مكان `data/itrack.db`، واحذف `itrack.db-wal` و`itrack.db-shm`، ثم شغّل الخدمة.

## ٦) التحديث
استبدل الملفات بالإصدار الجديد ثم أعد تشغيل الخدمة. ترحيلات القاعدة تُطبَّق تلقائيًا، والبيانات لا تُمس.

## ٧) الأمان باختصار
- كلمات المرور مُجزّأة (PBKDF2-SHA256، 310 ألف دورة). رموز الجلسات والدعوات تُحفظ مُجزّأة أيضًا.
- حد للمحاولات: ١٠ محاولات دخول فاشلة تُوقف الحساب ١٥ دقيقة.
- لا يُخدم إلا ملفات الواجهة. ترويسات CSP وHSTS ومنع التضمين مفعّلة.
- سجل تدقيق لا يُعدَّل لكل رفع واعتماد وإعادة، وكل دعوة وانضمام وإعادة تعيين.
- مهام «مهامي» خاصة بصاحبها، إلا ما يختار صاحبها إظهاره لمديره.
