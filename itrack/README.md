# ITrack — توثيق الإنجاز اليومي للفريق

منتج مستقل عن «مركز القيادة». الموظف يكتب ما أنجزه كل يوم مربوطًا بمسؤوليات توصيفه الوظيفي، ويرفعه. المدير يرى فريقه (على أي عمق)، ويعتمد أو يعيد للتعديل. مسؤول الجهة يدير الهيكل ويرى سجل تدقيق لا يُعدَّل.

## البنية
| الجزء | التقنية | الملف |
|---|---|---|
| الواجهة | PWA ثابتة بلا بناء، RTL، ثلاثة ثيمات | `index.html`, `js/app.js`, `js/core.js`, `styles.css`, `sw.js` |
| الخادم | Cloudflare Worker (مجاني) | `worker/worker.js` (ملف واحد يُلصق في المحرّر) |
| البيانات | Cloudflare D1 (SQLite) | المخطط داخل `worker.js` (ترحيلات مرقّمة تُطبَّق تلقائيًا) |
| الدخول | Firebase Authentication (مجاني) | `config.js` |

### الجداول
`orgs` · `departments` · `positions` (التوصيف، بإصدار يزيد مع كل تعديل) · `responsibilities` (لا تُحذف، تُعطَّل) · `members` (الدور، الإدارة، الوظيفة، المدير المباشر، الحالة) · `reports` (يوم لكل موظف: مسودة ← مرفوع ← معتمد/مُعاد) · `report_items` (النص، المسؤولية، الدقائق، الحالة: أُنجز/جارٍ/متعثّر + السبب) · `audit` (كل إجراء، مع نسخة كاملة مما رُفع).

### الصلاحيات (تُفرض في الخادم)
- **مسؤول الجهة**: كل شيء، والهيكل، والسجل الكامل.
- **مدير**: كل من تحته على أي عمق (استعلام شجري). يعتمد أو يعيد مع سبب إلزامي، أو يعلّق.
- **موظف**: تقاريره وتوصيفه فقط. مسودته لا يراها أحد حتى يرفعها.
- التقرير المرفوع مقفل؛ المعتمد نهائي. الكتابة المتأخرة حتى ٧ أيام وتُعلَّم «متأخر».
- الانضمام: المسؤول يضيف البريد ← الموظف ينشئ حسابه بنفس البريد ويؤكّده ← يُربط تلقائيًا. بريد غير مؤكد لا يُربط.

## النشر (مرة واحدة، من لوحة Cloudflare)
1. **D1**: Storage & databases ← D1 ← Create ← الاسم `itrack`.
2. **Worker**: Workers & Pages ← Create ← Worker ← الاسم `itrack-api` ← Deploy ← Edit code ← الصق `worker/worker.js` كاملًا ← Deploy.
3. **الربط**: Worker ← Settings ← Bindings ← Add ← D1 database ← الاسم `DB` ← قاعدة `itrack`.
4. افتح `https://itrack-api.<حسابك>.workers.dev/api/health` ⇒ يجب أن يظهر `{"ok":true,...}`.
5. ضع الرابط في `config.js` (`apiUrl`) ثم commit + push.
6. **Firebase** ← Authentication ← Settings: فعّل **إنشاء الحسابات** (Enable create). الأمان من الخادم: من لم يُضفه مسؤول الجهة لا يرى شيئًا. وأضف نطاق الاستضافة في Authorized domains.
7. افتح الواجهة (`/itrack/` على نفس استضافة المستودع) ← حساب جديد ← أكّد بريدك ← «إنشاء جهة».

## الاختبار (محليًا، بلا Cloudflare)
```bash
node --experimental-sqlite itrack/tests/worker.test.mjs     # الخادم: ٦٣ فحصًا (صلاحيات، دورة التقرير، التدقيق، التوصيف)
AXE=/path/to/axe.min.js node itrack/tests/e2e.js           # الواجهة كاملة: مسؤول + مشرف + موظفة، axe في الثيمات الثلاثة
```
`tests/d1shim.mjs` يحاكي D1 فوق node:sqlite ويوقّع رموز Firebase بمفتاح اختبار؛ `tests/server.mjs` يشغّل الواجهة والخادم معًا.

## خارطة الطريق
- **المرحلة ١ (هذه)**: الهيكل، التوصيف، التقرير اليومي، لوحة الفريق، الاعتماد/الإعادة، السجل.
- **المرحلة ٢**: مهام مُسندة من المدير بموعد ومتابعة وربطها ببنود التقرير، تنبيه من لم يرفع (Cron)، تذكير يومي.
- **المرحلة ٣**: مؤشرات أداء لكل وظيفة، تقرير شهري، لوحة المدير العام، تصدير Excel/PDF، مرفقات.
- النقل لسيرفر الشركة: نفس SQL على SQLite/PostgreSQL، واستبدال التحقق من Firebase بنظام دخول الشركة.
