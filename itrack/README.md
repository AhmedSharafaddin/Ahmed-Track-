# ITrack — العمل اليومي والمهام في تطبيق واحد

تطبيق واحد يُثبَّت عند أي جهة: **العمل** (تقارير يومية، اعتماد، فريق، هيكل، سجل) و**مهامي** (واجهة مركز القيادة كاملة: مهام، أهداف، تركيز، لوحة، صوت ومحضر اجتماع). يعمل بطريقتين بنفس الكود:
- **سيرفر الجهة** (`server/`): Node.js + SQLite، بلا إنترنت وبلا Firebase. دليل التثبيت: [`server/INSTALL.md`](server/INSTALL.md).
- **Cloudflare** (التجربة الحالية): Worker + D1 مجانًا.

الموظف يكتب ما أنجزه كل يوم مربوطًا بمسؤوليات توصيفه الوظيفي، ويرفعه. المدير يرى فريقه (على أي عمق)، ويعتمد أو يعيد للتعديل. مسؤول الجهة يدير الهيكل ويرى سجل تدقيق لا يُعدَّل.

**المتابعة** (للمدير): يُسند مهامًا تصل لـ«مهامي» عند الموظف مباشرة، والواجبات اليومية/الأسبوعية/الشهرية تتولد من التوصيف تلقائيًا. الموظف يرفع النسبة والتفاصيل والصور ويعلّق، والمدير يعتمد أو يعيد، ويرى لوحة مؤشرات (الإنجاز، الالتزام بالموعد، الموزون بالأولوية، الحِمل، مخاطر التأخير) مع قائمة ولوحة Kanban وتقويم وتصدير Excel. كل ما يخرج من شبكة الجهة (الذكاء الاصطناعي، Webhooks، مفاتيح API، التقويم) معطّل افتراضيًا ويُفعَّل بمفتاح: [`docs/IT-REVIEW.md`](docs/IT-REVIEW.md).

### الجداول
`orgs` (+ `settings`: مفاتيح التشغيل والقواعد والعطلة) · `departments` · `positions` (التوصيف، بإصدار يزيد مع كل تعديل) · `responsibilities` (لا تُحذف، تُعطَّل) · `members` (الدور، الإدارة، الوظيفة، المدير المباشر، الحالة) · `reports` (يوم لكل موظف: مسودة ← مرفوع ← معتمد/مُعاد) · `report_items` (النص، المسؤولية، الدقائق، الحالة: أُنجز/جارٍ/متعثّر + السبب) · `audit` (كل إجراء، مع نسخة كاملة مما رُفع) · `pdocs` (مهام «مهامي»، وفيها المسندة `a.*` والواجبات `d.*`) · `comments` · `files` (صور مضغوطة BLOB) · `notes` (التنبيهات) · `api_keys` (مجزّأة) · `feeds` (روابط التقويم، مجزّأة).

### المهام المسندة والواجبات (هجرة ٦)
- المهمة المسندة وثيقة في مهام الموظف نفسه ⇒ يعمل عليها بكل أدوات «مهامي» (اليوم، المصفوفة، التركيز، الخطوات). **الأولوية = مربع المصفوفة** (حرجة = مهمة وعاجلة).
- **القفل في الخادم**: العنوان والموعد والأولوية والتقدير وحالة الاعتماد والصور لا يغيّرها الموظف؛ أي محاولة تُعاد بصمت (لا رفض، كي لا تسقط دفعة المزامنة) ويتغيّر `updated_at` فيسحب الجهاز النسخة الصحيحة. لا حذف، ولا تزوير مهمة مسندة على مهمة شخصية، والمعرّفات `a.*`/`d.*` محجوزة.
- **الواجبات**: مسؤولية في التوصيف بتكرار يومي/أسبوعي/شهري (والأسبوع يبدأ السبت) تتولد عند القراءة بمعرّف ثابت لكل فترة، بلا Cron. الفائت غير الملموس يُزال من قائمة الموظف ويُحسب «فائتًا» من التوصيف نفسه.
- **الإنجاز**: الخادم يختم `doneAt`، والنسبة ١٠٠، وحالة الاعتماد «بانتظار» إن طُلب. «تتطلب صورة» ⇒ لا تُغلق قبلها. الإعادة تفتحها بملاحظة إلزامية.
- **المؤشرات** (`/api/metrics`): الإنجاز = المنجز ÷ (المنجز + ما فات موعده)، الالتزام = في الموعد ÷ المنجز، الموزون (٣/٢/١)، الاعتماد، الحِمل (المتبقي المقدّر ÷ ساعات ٧ أيام)، التقارير، وخطر التأخير بقواعد معلنة (فات الموعد، تأخر عن الجدول، يستحق قريبًا والإنجاز دون النصف، متعثّرة).

### الصلاحيات (تُفرض في الخادم)
- **مسؤول الجهة**: كل شيء، والهيكل، والسجل الكامل.
- **مدير**: كل من تحته على أي عمق (استعلام شجري). يعتمد أو يعيد مع سبب إلزامي، أو يعلّق.
- **موظف**: تقاريره وتوصيفه فقط. مسودته لا يراها أحد حتى يرفعها.
- التقرير المرفوع مقفل؛ المعتمد نهائي. الكتابة المتأخرة حتى ٧ أيام وتُعلَّم «متأخر».
- **صندوق الوارد** (`/api/inbox`): المدير يرى التقارير المرفوعة التي تنتظر مراجعته (آخر ١٤ يومًا، الأقدم أولًا) مع شارة عدد على «الفريق»، والموظف يرى تقاريره المُعادة له للتعديل أعلى «يومي».
- **CORS**: الخادم يقبل الطلبات من `https://ahmedsharafaddin.github.io` والتطوير المحلي فقط. عند النقل لنطاق آخر أضف متغير `ALLOWED_ORIGINS` في إعدادات الـWorker (مفصول بفواصل).
- الانضمام: المسؤول يضيف العضو ← تظهر رسالة دعوة فيها رابط `#/code/XXXX-XXXX-XXXX` (صالح ١٤ يومًا، مرة واحدة) ← يفتحه ويختار كلمة مرور ← يُربط بمكانه. تطابق البريد وحده لا يكفي (حماية بين الجهات على نفس الخادم).
- نسيان كلمة المرور: المسؤول يصدر «رمز إعادة تعيين» (٢٤ ساعة) — لا حاجة لخادم بريد. لا يُصدَر لحساب ينتمي لجهات أخرى.
- `SIGNUP=invite` (افتراضي على سيرفر الجهة): أول حساب فقط بلا رمز، والجهات الجديدة ينشئها المسؤولون.

## التكامل (لأنظمة أخرى)
كل طريقة بمفتاح في «الهيكل ← التشغيل والتكامل»، وكل تغيير في السجل:
- **Webhooks**: `POST` JSON لكل حدث (`task.assigned|done|blocked|approved|returned|cancelled`, `comment.created`, `report.submitted`) فيه `text` جاهز لـSlack/Teams/Google Chat، وترويسة `x-itrack-signature: sha256=HMAC_SHA256(secret, body)`.
- **مفاتيح API** (`Authorization: Bearer itk_…`): تعمل باسم المسؤول الذي أصدرها، والجهة من المفتاح، وعلى المسارات المعلَّمة فقط: `GET /api/bootstrap`, `GET /api/metrics`, `GET /api/assigned`, `GET /api/task/:member/:task`, `GET /api/export.csv?type=people|tasks`, `POST /api/assign`, `PATCH /api/assign/:member/:task`, `POST /api/assign/:member/:task/{review,cancel}`. حد ٣٠٠٠ طلب/ساعة للمفتاح.
- **التقويم**: كل موظف ينشئ رابطًا سريًا (`/api/ics/ic_….ics`) يشترك به في Outlook/Google Calendar.
- **CSV**: التصدير يفتح في Excel بالعربية (BOM)، والخلايا التي تبدأ بـ`= + - @` تُحيَّد (حماية من حقن الصيغ).

## مساحتي الشخصية (`my/`)
واجهة «مركز القيادة» كاملة (مهام، مجالات، أهداف، مصفوفة، لوحة، تركيز) داخل ITrack. بياناتها وثائق خاصة بصاحبها في خادم ITrack (`/api/p`)، والمهمة التي يضع عليها صاحبها «يراها مديرك» تظهر لمن فوقه فقط (`/api/team/tasks`). الدخول بنفس حساب ITrack. الملف `my/index.html` مولَّد: `node itrack/tools/make-my.mjs` بعد أي تعديل على `index.html` في الجذر.

## النشر (مرة واحدة، من لوحة Cloudflare)
1. **D1**: Storage & databases ← D1 ← Create ← الاسم `itrack`.
2. **Worker**: Workers & Pages ← Create ← Worker ← الاسم `itrack-api` ← Deploy ← Edit code ← الصق `worker/worker.js` كاملًا ← Deploy.
3. **الربط**: Worker ← Settings ← Bindings ← Add ← D1 database ← الاسم `DB` ← قاعدة `itrack`.
4. افتح `https://itrack-api.<حسابك>.workers.dev/api/health` ⇒ يجب أن يظهر `{"ok":true,...}`.
5. ضع الرابط في `config.js` (`apiUrl`) ثم commit + push.
6. (اختياري) الذكاء الاصطناعي: Bindings ← Add ← Workers AI ← الاسم `AI`.
7. افتح الواجهة (`/itrack/` على نفس استضافة المستودع) ← حساب جديد ← «إنشاء جهة». لم يعد Firebase مطلوبًا.

```bash
node itrack/tests/auth.test.mjs        # الحسابات والرموز وكلمات المرور الشائعة والذكاء الاصطناعي ومفتاحه: ٦٦ فحصًا

node itrack/tests/server.smoke.js      # سيرفر الجهة فعليًا: ملفات، ضغط، CSP، نسخ احتياطي، الصفحتان بلا إنترنت: ٢٤ فحصًا
AXE=/path/to/axe.min.js node itrack/tests/e2e.js        # الواجهة كاملة بالمتصفح: ٦٤ فحصًا مع axe
node itrack/tests/xss.e2e.js                            # حقن XSS في كل حقل يكتبه مستخدم عبر ٢٤ شاشة بثلاثة أدوار + عنصر ضبط: ١١ فحصًا
AXE=/path/to/axe.min.js node itrack/tests/work.e2e.js   # مسار الإسناد كاملًا (مدير لابتوب + موظف جوال): ٥٨ فحصًا مع axe وعرض ٣٩٠px وزمن الاستجابة
```

## خارطة الطريق
- **المرحلة ١ (هذه)**: الهيكل، التوصيف، التقرير اليومي، لوحة الفريق، الاعتماد/الإعادة، السجل.
- **المرحلة ٢ (منجزة ٢٠٢٦-١١-٠٨)**: الإسناد، الواجبات الدورية، الاعتماد، الصور، النقاش، التنبيهات بقواعد، المؤشرات ولوحة المدير، Kanban/تقويم، تصدير Excel، التكامل (Webhooks/API/ICS)، الذكاء بمفتاح، التقرير يُملأ من المهام، Ctrl+K.
- **المشاريع (٢٠٢٦-١١-٠٩)**: تبويب «المشاريع» تحت المتابعة: بطاقات بنسبة موزونة بالأولوية وصحة (على المسار/متأخر/متعثّر)، صفحة مشروع بالأشخاص والمهام، إسناد داخل المشروع، إعادة تسمية تنتشر لمهام الموظفين، أرشفة وإعادة تفعيل. الخادم: `/api/projects` (هجرة ٧). الاختبارات: `tests/projects.test.mjs` (٤٦) و`tests/projects.e2e.js` (٣٣ مع axe وXSS).
- **استيراد التوصيف من ملف (٢٠٢٦-١١-٠٩)**: في «الهيكل ← الوظائف والتوصيف ← وظيفة جديدة»: ارفع xlsx أو docx أو pdf أو csv أو الصق نصًا فتتحول بنوده إلى مسؤوليات (تكرار/أولوية/مدة إن وُجدت) تراجعها ثم تحفظ. محلي بالكامل بلا ذكاء اصطناعي. PDF عبر pdf.js المضمَّنة (انظر IT-REVIEW). الاختبارات: `tests/import.test.mjs` (٢٧ منطق) و`tests/import.e2e.js` (٤٠ على ملفات حقيقية في `tests/fixtures`، يولَّد بـ`make-fixtures.py` و`make-pdf.js`).
- **التالي (بعد تجربة حقيقية)**: مراحل مخصصة لكل قسم، قوالب مهام، تقرير شهري PDF، تنبيه Push على الجوال، دخول موحّد.
- **منجز**: سيرفر الجهة (`server/`)، حسابات داخلية، الذكاء الاصطناعي بمزوّد قابل للتبديل.
- لاحقًا: دخول موحّد مع نظام الشركة (Microsoft 365 / LDAP) إن طُلب، وPostgreSQL إن تجاوز الحجم SQLite (آلاف المستخدمين)، وتطبيق متاجر (TWA) بشاشة «عنوان خادم جهتك».
